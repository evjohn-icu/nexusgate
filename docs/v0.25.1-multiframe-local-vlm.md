# v0.25.1 目标：Local Multiframe Analysis v1

> 对应 roadmap Phase 1。这版的目标不是"支持更多模型"，而是改变视频分析的
> 分工方式：**Timingdex 拥有时间轴，VLM 只理解画面**。

## 为什么

旧的 `openai_video` 协议把整段 proxy base64 后作为 `video_url` 发给 VLM。
对本地模型（llama.cpp / LM Studio / vLLM / SGLang）这条路不可行：整段视频
体量大、无分段概念、模型要自己猜时间轴。更重要的是分工错误——shot 边界是
检索的命根子，不能交给一个"顺便"做检测的模型。

新协议 `openai_multiframe`：

```
video → deterministic segmentation → representative frames → timestamps
     → transcript slice → local multimodal model → structured shot metadata
```

## 部署形态

目标硬件分层（本期只打通 Hub 本地路径，Worker 不在范围）：

| 层 | 硬件 | 职责 |
|----|------|------|
| Hub | CPU / iGPU | scan / probe / thumbnail / proxy / scene detection |
| GPU worker（可选） | 8–16GB VRAM | local VLM（Q4 级别即可） |
| Cloud（可选） | — | 困难素材 / fallback |

一个 8GB 显存机器即可跑通 Q4 的 Qwen3-VL-4B 多帧分析。

## 配置

```json
{
  "providers": {
    "vision_primary": "local_vlm",
    "local_vlm": {
      "enabled": true,
      "protocol": "openai_multiframe",
      "base_url": "http://127.0.0.1:8080/v1",
      "path": "chat/completions",
      "model": "Qwen3-VL-4B-Instruct",
      "timeout_seconds": 300
    },
    "shot_detection": {
      "enabled": true,
      "mode": "ffmpeg_scene",
      "scene_threshold": 0.3
    }
  }
}
```

- `shot_detection.mode` 二选一：`ffmpeg_scene`（内置，零新依赖）或
  `external_command`（外部 wrapper，stdin `{"video_path","duration_ms"}` →
  stdout `{"shots":[{"start_ms","end_ms"}]}`，如 PySceneDetect）。
- **未配置 shot_detection 时**：multiframe 路径回退双 pass——现有 VLM
  window analysis 出边界与资产级分析，multiframe 逐 shot 精修。这意味着
  纯本地部署（无 video-capable fallback）**必须**配置 detector，否则分析
  作业以永久错误终止并指明 remedy。
- detector 身份（命令行为 hash / `ffmpeg-scene-<threshold>`）写进 model_run
  的 request_json：换 detector 或调阈值会自动重新分析，绝不复用旧结果。

## 每 shot 采样规则（boundary-aware）

| shot 时长 | 帧数 | 位置 |
|-----------|------|------|
| < 2s | 2 | 20%, 70% |
| 2s–30s | 4 | 10%, 35%, 65%, 90% |
| > 30s | 6 | 5%, 20%, 40%, 60%, 80%, 95% |

帧从 **proxy** 提取（已做色彩校正与降采样），768px JPEG，scratch 目录用完
即删，不占 cache。帧时间戳（asset 相对）与 shot 窗口、transcript 切片一起
写进 prompt；模型返回 schema 里**没有时间字段**。

## Provenance

- detector 模式：一个 run（`multiframe-analysis-v1`），含 summary 调用 +
  逐 shot 调用，raw 全部留档。run 的 input hash 由 detector 身份 + sampler
  派生：换 detector（或调阈值）后重试/重跑必然产生新 run，绝不复用旧结果。
- 双 pass：两个 run——pass-1（`footage-analysis-v4`，video 成员署名）持有
  资产级 analysis；pass-2（`multiframe-refinement-v1`）用
  `ReplaceAssetShots` 替换 shot 行并标记 committed，shot 归属精修 run。
  精修失败 = pass-1 结果保留（降级），run 标记 failed，reanalyze 可重试。
- summary 调用的 transcript 有界（4000 字符头尾摘录）：长片字幕不会挤爆
  小模型上下文。

## 已知边界（诚实声明）

- `audio_type`/`has_speech`：帧模型听不见。`has_speech` 由 transcript
  判定；`audio_type` 由 summary 调用按 transcript 推断，无法保证。
- `people_count`：per-shot schema 无 count，依赖 summary 调用。
- 帧提取是 keyframe 级近似（与 thumbnail 同路径）；批量提取（select 过滤
  器）记为后续优化。
- Worker 路径保持 `openai_video` 经 Hub proxy；multiframe 是 Hub 本地路径。

## Eval

```bash
# 每模型一个数据目录（含各自的 config.json）
timingdex-eval run --corpus ./corpus --data-dir ./eval/qwen --label qwen3vl-4b
timingdex-eval run --corpus ./corpus --data-dir ./eval/gemini --label gemini-flash
timingdex-eval score --corpus ./corpus --data-dir ./eval --labels qwen3vl-4b,gemini-flash
```

corpus 布局：`clips/*.mp4` + `ground_truth.json`
（`[{query, language, expected: [{asset, start_ms, end_ms}]}]`）。score 用
产品同款 hybrid 检索（默认权重）与 golden 同口径指标，输出
R@10/P@10/FP/RT factor/帧数对比表 + 逐 query 明细（丢了什么、多召回什么）。
