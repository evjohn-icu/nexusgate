# v0.28.2 Search Evidence Correctness

## Scope

This release tightens the boundary between retrieval and claims in Search v2.
Evidence is collected from every source before the state is selected, so an
explicit description negation cannot be hidden by a structured positive
observation. Sources are emitted in the stable order `objects`, `actions`,
`tags`, `mood`, `description`, `transcript`.

Positive constraints are `contradicted` when the description explicitly says
the term is absent, including when structured fields also contain the term.
Structured positive plus a positive description is `confirmed` with both
sources. A negated constraint treats structured positives as observed forbidden
content (`confirmed`, excluded), positive description mentions as `possible`
(`excluded`), and explicit absence as `unknown` (kept; absence is not asserted).

## Exact Speech Phrases

Speech retrieval still uses an efficient SQL token prefilter, but candidates
only score after exact aligned-span validation. Every phrase component must
match in order without reusing a span. ASCII components require an exact whole
aligned word. CJK components match contiguous rune sequences even when ASR
spans split or pack the sequence. Adjacent matched spans may be separated by at
most 1500 ms, and spans outside the shot interval are not considered.

Partial, reordered, missing, substring, and over-gap matches do not become
speech evidence. A complete match is `possible`, because speech mention is not
visual proof.

## Verification

The regression coverage includes conflict matrices, direct phrase matching,
SQLite exact-ranking fixtures, service evidence, and API response semantics.
The query profile is bumped to `v2-profile-2` so cached query feedback does not
cross the changed evidence/phrase behavior.
