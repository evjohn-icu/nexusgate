## 1. 设计方向：证据台

这不是一个仪表盘，是一张**看片记录台**。它的视觉词汇从这个行当自己的器物里来：
时间码、刻度、监视器、场记单。

### 三条不可违反的规则

**规则一 · 界面是中性灰的。**
彩色只用来表示状态，绝不用来做装饰、做品牌、做「好看」。理由来自这个产品本身：
调色台、监视器、剪辑软件的界面全是中性灰，因为**工具不能污染你对画面的判断**。
所以主按钮是高对比中性色（深色模式白底黑字，浅色模式黑底白字），不是蓝色。

**规则二 · 五档证据，全站同一套。**

| 档位 | 令牌 | 视觉 | 用在哪 |
|---|---|---|---|
| 确认 | `--ev-confirmed` | 绿，实心底 | confirmed / 正常 / 已批准 / 在线 / succeeded |
| 可能 | `--ev-draft` | 紫，**虚线**边 | possible / AI 起草 / 待审核 / running |
| 注意 | `--ev-attention` | 琥珀，实心底 | 等用量 / 降级 / 延后 / deferred |
| 反证 | `--ev-contradicted` | 红，实心底 | contradicted / 失败 / 不再重试 / 已吊销 |
| 未知 | `--ev-unknown` | **灰，点线边，无底色** | unknown / 未配置 / 空闲 / pending |

「未知」永远是灰的点线，**永远不是红的**。这不是审美偏好，是这个产品的核心承诺：
搜索没找到人不等于确认无人（`CLAUDE.md`：*unknown is never「确认无人」*）。把 unknown
画成红色或画成「否」，就是在界面上撒谎。同理，「可能」用虚线而不是实线，因为它是
机器断言、尚未被人确认——这正好也是 `agents may draft; humans approve` 的样子。

**规则三 · 数据走等宽体。**
时间码、计数、ID、哈希、文件大小、日期、状态名、栏目名，一律 `--font-data` +
`tabular-nums`。界面的性格就在这里：**每个数字都对得齐，每个标签都是小型大写的等宽标记**，
它读起来像一台仪器，而不是一个网站。

### 签名件：刻度（`.tickrule` / `.chain`）

一条带刻度的轨。凡是「整体中的一段」都用它，而且**只用它**：

- 素材卡上的镜头时间轴（真实镜头边界，命中段带证据色）
- 处理进度页的流水线链 `probe → derive → speech_gate → transcribe → analyze → index`
  —— **每一格显示阶段名与它做什么，不显示计数**。`JobSummary` 只有
  `pending/running/succeeded/failed/terminal/deferred/total` 六个总数，没有按作业类型
  的分解；而 `/api/v1/jobs` 返回的是**样本不是计数**（`internal/domain/pipeline.go`
  的注释记着这个坑：曾经因此把几千个已完成作业显示成「0 已完成、100 待处理」）。
  在浏览器里凑一个每阶段计数 = 把那个 bug 重新种回去。链的价值是让人看懂素材要过哪几关、
  现在卡在哪一关，这两件事不需要计数。
- 任务进度条、存储占用条

它是量化的，不是装饰。当前页在侧栏导航上被点亮的那一格用同一个装置（品牌色刻度条），
处理链里「正在跑的阶段」也用同一个装置——**一个想法，全站复用，背后都有真实信息**。

### 字体：不许有网络字体

这是本地优先工具，会在断网的 NAS 上跑。任何 `fonts.googleapis.com` 都是错的
（离线即失效，且等于每次开页都向 Google 报到）。所以三个角色全部用系统栈：
显示体 / 正文体共用 `--font-ui`，数据体用 `--font-data`。

中文排版两个必须改的旧毛病：

- 现有页面在 h1 上写 `letter-spacing:-.04em`。**负字距对中文是错的**，会挤成一团。
  新规格是 `+.01em`。
- 行高 `--lh-cjk:1.75`。中文正文需要比西文松，1.5 太挤。

侧栏 slogan 用英文 `LOCAL FOOTAGE INDEX`，是对 `CLAUDE.md`「产品 / UI 文案用中文」的
一处**已获批准的例外**（EV 2026-08-21 确认）。等宽小型大写（`letter-spacing:.16em` +
`text-transform:uppercase`）这个处理对中文不成立——中文没有大小写，字距拉开只会散。
换成中文它就只是一行普通小字，标识性没了。全站其余文案仍然一律中文。

## 3. 兼容层（可直接粘贴，附在上面那块之后）

这一层把**现存的旧类名**接到新配方上。它的存在只有一个理由：改 `app_shell.go`
一个文件，全站立刻换脸，页面 HTML 一行不动，18 个锚点补丁一个都不用碰。

映射是逐个核对过实际用法的，**不是按名字猜的**。两个陷阱已经踩过并绕开：

- `.danger` 在 `library_roots_page.go` 里是 `<div>` 警告框，不是按钮 —— 所以只映射 `button.danger`
- `.state` 在 `settings_page.go` 里是 `<div>` 容器，不是徽标 —— 所以只映射 `span.state`
- `.legend i` 是颜色圆点，不是徽标 —— 单独给圆点配方

另外两个是**做浅色回归时实测撞出来的**，不是推演的：

- **旧令牌名不能直接删。** 全仓库还有 **190 处** `var(--ui-*)` 引用，分布在 10 个文件
  （`--ui-border` 62 处、`--ui-bg` 27 处、`--ui-surface-inset` 19 处……）。无效的 `var()`
  会让**整条属性被浏览器静默丢弃**——不报错、不回退，只是样式没了。所以兼容层第一节
  把旧名指向新令牌。（`--space-*` / `--radius-*` / `--text-*` 定义过但零引用，可以直接死掉。）
- **`input` 光写裸标签不够。** 页面里用的是 `input[type=number]` 等属性选择器，
  特异性 (0,1,1) 高于裸 `input` (0,0,1)。不把类型逐个列进来，设置页的输入框在浅色模式下
  仍然是深蓝底——这个 bug 是截图截出来的。

所以：**兼容层是第一步，不是终点。** 每个页面仍需按任务书做一次自己的清理，
清完就把该页的旧类名从兼容层里删掉。全部清完时，兼容层这一节应当整节消失。
