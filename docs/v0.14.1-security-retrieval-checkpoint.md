## 必须先修：Hub 安全基线

**状态：已完成代码与自动化回归验证。**

- Hub 首次启动会创建或复用原始 `admin-token`（精确 0600，重启后复用；数据目录精确
  0700，发现符号链接或不安全权限时拒绝而不修复）；配对、Hub 节点、根目录、
  扫描、工作流、管线、Tag 治理、总结和 Repurpose 写入必须携带管理员 Token。
- `/workers` 仅将管理员 Token 保留在页面内存，可生成一次性配对 Token；不写入
  浏览器存储。
- Compose 默认不发布 Hub 端口；Worker Provider Key 短时交付默认关闭，文档已
  写明其上游 Key 风险边界。

当前 `POST /api/v1/hub/worker-pairings` 没有 Hub 管理员认证。攻击者可创建
配对 Token、注册一个自称支持 Provider 操作的 Worker、租约任务并请求临时
Provider 凭证。这会暴露上游长期 API Key。

同时，`docker-compose.yml` 默认将 Hub 绑定并发布到 `0.0.0.0:8787`，而
Worker Compose 默认 URL 仍为 HTTP。这与 NAS Hub 的威胁模型不一致。

### v0.14.1 安全验收目标

1. Hub 首次启动生成管理 Token，写入 `$DATA_DIR/admin-token`，权限精确为
   `0600`，并在重启后复用；支持从安全环境变量显式提供，但不得进入数据库、
   浏览器存储或日志。配对/节点 Token 才在数据库中存储 SHA-256 摘要。
2. `/api/v1/hub/*`、所有扫描/写入/管理接口必须要求管理 Token。
3. Worker 协议仍以 Worker Token 认证；`worker/enroll` 只能凭已认证的配对
   Token 运行，且配对 Token 的创建必须要求管理 Token。
4. Compose 默认仅 `expose` Hub 端口给内部网络，不再默认 `ports` 发布；外部
   UI 通过用户显式配置的 HTTPS 反向代理进入。
5. Compose Worker 默认使用 HTTPS 和配对时固定的证书指纹；删除默认 HTTP
   通信路径。
6. “凭证租约”文案改为“短时交付租约”。其 TTL 只限制 Hub 发放窗口，不能使
   已交给 Worker 的上游 API Key 失效。默认关闭 Worker Provider Key 下发，
   在完成 Hub Provider Proxy 或取得上游可撤销短期 Token 前，仅可由明确的
   风险开关启用。
7. 回归测试覆盖完整攻击链：无管理 Token 无法创建 pairing、注册恶意 Worker、
   枚举 Hub 节点或请求凭证。

## 接着修：中文检索正确性与规模

**状态：已完成代码与自动化回归验证。**

- `asset_search` / `asset_shot_search` 均以共享 CJK Bigram 分词写入，查询使用
  同一 phrase-preserving MATCH 构造；不再使用 CJK `instr(...)` 正常检索路径。
- `0012_v0141_cjk_bigram_fts.sql` 置 pending 标记，Hub 迁移时回填并原子标记
  ready，可从中断升级恢复。

当前库已有中文 `instr(...)` 兜底，因此双字 CJK 查询不会必然无结果；但该路径
是全表扫描，不能作为正式检索方案。

不要改为 SQLite `trigram`：它不能匹配少于三个字符的查询，无法解决 `夜景`、
`街道`、`雨夜` 等核心需求。

### 采纳方案：应用层 CJK 重叠 Bigram + unicode61

1. 新建单一的 CJK FTS 分词函数：连续 CJK 生成重叠 bigram；拉丁和数字维持
   原样、小写化；正表保存原文。
2. 仅将分词结果写入 `asset_search` 和 `asset_shot_search` FTS 影子表。
3. 查询也用同一函数构造 MATCH 表达式。连续 CJK bigram 应优先使用 FTS5
   phrase/proximity 保持顺序，而不是无条件 `AND`。
4. 新 migration 清空 FTS 影子表并以带完成标记的 Go backfill 重建，保证已有
   素材库升级后立即可检索。
5. `discovery.semanticTokens` 复用 CJK 分词边界；增加独立测试。
6. 为 `街道`、`雨夜`、`走路`、`一个人`、`雨夜街道`、中英混合以及负例
   `城市` / `海滩` 建立回归测试。

## 后续检索清理（不阻塞 v0.14.1）

- Hybrid Search 目前对语义向量全库扫描，且确定性 hash 特征权重为 70%。
- 应先由 FTS/bigram 召回 Top-K，再做语义重排。
- hash 特征只能作为辅助，不应成为主排序信号；需要单独的基准测试和权重评估。
- `HeuristicDraft` 的城市/人/夜景模板需要降低为真正的保底策略，不能替代检索
  证据。
