# v0.38.0-alpha Release Notes

Status: the failure-classification round is complete and its verification
record is below. These notes cover exactly the two commits that follow the
published `v0.31.0-alpha` baseline — `45bad84` and `3835be7`; together they
are the entire content of this release, and nothing else is claimed as part
of it. Measured values retain the precision reported by their runs.

Baseline: `v0.31.0-alpha` (published, 2026-09-09). Both commits in this
release are failure-classification fixes, and both were driven by the same
real run: a 50-file, 189.5 GiB travel library pushed through the full
pipeline on a real NAS. It produced 6 derive failures, and every one of them
used to land in `unknown` — the bucket on `/progress` that carries neither a
label nor a repair link.

## What Changed

### Failure-classification round (2 commits, 2026-09-09)

- **`UnsupportedMedia` has its first producer, so RAW sources stop landing
  in the unlabeled bucket.** (45bad84) Four of the six derive failures were
  "RAW preview renderer unavailable", and they all fell into `unknown`.
  `media.ResolvePlan` has always refused RAW sources with a
  `*PreviewRenderError` carrying the exported `Code`
  `PreviewErrorRendererUnavailable`, and the classifier reads that field
  rather than the message text, so exactly this identity now maps to
  `domain.JobFailureCategoryUnsupportedMedia` — an identity whose comment
  had read "No sentinel produces it yet" since it was written. The branch
  sits after the disk-full guard on purpose, and it is deliberately **not**
  marked permanent: disk-full is the outcome that heals itself and must keep
  its retry, a RAW preview renderer may yet be added, and the refusal
  happens before any byte of the file is read, so a retry costs almost
  nothing. Nothing else about the category changes.

- **A missing preview LUT got a name of its own, and the failure-category
  inventory got a single source of truth.** (3835be7) Two Apple Log assets
  in the same library failed with "Apple Log preview needs LUT" and also
  landed in `unknown`. The semantically nearest category, `configuration`,
  is hard-bound to `/providers` in `internal/api/progress_page.go`'s
  `issueRepairRoutes`, but `preview_lut_path` is a `config.json` key —
  linking to a page that cannot fix the problem is worse than offering no
  link at all. The new `domain.JobFailureCategoryPreviewLUTMissing`
  therefore carries accurate labels in all five languages and deliberately
  **no repair link**. The product does not distribute a LUT; the remedy is
  the operator's own copy pointed at `preview_lut_path`, and the day a page
  exists that can set that key is the day this category earns a link.

  The larger half is the guard. Deleting an entire `issueLabels` entry used
  to leave every test green, because that guard walked a hand-maintained
  string slice in the test file. `domain.AllJobFailureCategories` is now the
  single source of truth, and three checks walk it: the progress-page label
  guard, the spelling-stability table, and the retryable truth table.
  Retired `budget_exhausted` stays in the inventory on purpose: nothing
  produces it any more, but historical rows still carry it, and the issues
  view must keep labelling those rows.
