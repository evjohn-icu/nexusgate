# v0.15：素材拍摄记忆与 Provider 通道

v0.15 的目标不是把素材库变成剪辑器，而是让素材具有可浏览的拍摄上下文，并让
Hub 能以安全、可维护的方式使用多个模型账号。

## 素材拍摄记忆

扫描与 Probe 后，NexusSlate 会保存相机厂商/机型、拍摄时间、色彩/RAW 分类和可用
的来源证据。支持 Blackmagic、DJI、Sony、Canon、Apple、GoPro、Insta360、Panasonic、
Nikon、Fujifilm、RED 与 ARRI 的常见标识与侧车候选；这是一层识别与路由能力，不是
对每一种专有 RAW 解码器的承诺。

处理完成时，系统只会在同一素材根、相同相机身份、时间间隔不超过 30 分钟，或存在
明确 Reel/Session 标记时，建立自动拍摄 Session。它不会修改原片或侧车文件。库页可按
拍摄日期、地区标签、相机和 Session 过滤；默认 API 不暴露原始绝对路径或精确 GPS。

## 色彩与 RAW 边界

- SDR：按普通预览流程处理。
- HLG/PQ：交由 HDR → SDR Rec.709 预览流程。
- Apple Log / 其他 Log：必须存在匹配 LUT；缺失时显示“需要 LUT”。
- BRAW、R3D、ARI、CRM、N-RAW、ProRes RAW 等：可靠分类并保留原始色彩信息；没有
  兼容 Renderer 时显示“等待兼容 Renderer”，不会生成误导性 SDR Proxy。

视频理解、缩略图和时间轴帧只应使用已经完成正确色彩渲染的 SDR 派生文件；NLE 导出
仍应引用原始文件和原始色彩信息。

## Provider 通道

打开 `/providers`，临时输入 Hub 管理 Token 后，按能力创建通道：Video analysis、ASR、
Embedding、Tag curation 或 Repurpose。一个通道可以有多个同 Provider Key，供 Hub 在同一
能力内做并发限制、轮换、失败冷却、重试和有序 fallback。

API Key 只会从当前管理员请求写入 Hub 的加密密钥库：

```text
$NEXUSSLATE_DATA_DIR/provider-secrets/     mode 0700
└── provider-secrets.enc                  mode 0600
```

SQLite 仅保存不可逆的 SecretRef 和通道元数据；列表 API 只显示“Key 已配置”。页面不使用
localStorage/sessionStorage，Worker 配置也不保存 Provider Key。

Provider 通道会实际接入 Video analysis、ASR、Embedding、Tag curation 与 Repurpose。
当没有可用的通道时，系统保留既有环境变量/配置文件 Provider 作为兼容回退；对于原本有
确定性/启发式回退的摘要、标签治理和翻新策划流程，也不会因为新增通道层而变成失败。

## Worker 安全边界

Worker 可处理 NAS 上的挂载素材、生成派生文件并把结果传回 Hub，但 v0.15 不向 Worker
下发长期上游 Provider Key。所谓“短时租约”无法撤销已经交给设备的第三方 Key，因此该
端点固定拒绝。未来只有两种安全升级路径：由 Hub 代理 Provider 请求，或使用 Provider
本身签发的短期、可撤销凭证。

## 仍需实机验收

v0.15 已通过完整 Go 测试、静态检查与 Linux x64/Linux ARM64/Windows x64 构建；仍需在
目标 NAS、Windows 独显 Worker、Linux x86 Worker 与 ARM Worker 上各跑一轮真实素材。特别
是应覆盖一个 HLG/PQ 素材、一个带 LUT 的 Apple Log 素材和一个专有 RAW 素材，以确认它们
分别进入正确的预览或“等待兼容 Renderer”状态。完整步骤见
[operations guide](v0.15-operations.md)。
