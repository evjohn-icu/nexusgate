# v0.31 素材能力提供层

> 部署走查见 [v0.31 部署指南](v0.31-deployment.md)；能力面的 Agent 契约与
> MCP 使用见 `skills/timingdex/`（SKILL.md、references/api-contract.md、
> references/mcp-usage.md）。

本轮让 Timingdex 成为 **ChatCut 类 AI 剪辑前端的底层素材能力提供方**：产品中立的
稳定能力契约，不是任何单一产品的专用胶水。新增词级转录稿读取端点，Agent 契约升版到
v0.15，MCP 客户端补齐跨机部署的证书指纹钉扎，并提供 Claude Code 插件打包。ChatCut
只是本契约的消费者之一。

## 能力面盘点

转录稿驱动的剪辑前端需要六项能力，四项此前已具备，本轮补齐第五项：

| # | 能力 | 状态 | 入口 |
|---|---|---|---|
| 1 | 知道库是否可用 | 已具备 | `GET /api/v1/health`、`/hardware`、MCP `inspect_library` |
| 2 | 按语义/语音找素材（带证据） | 已具备 | `POST /api/v1/search/shots`、MCP `search_shots` |
| 3 | 读镜头切分 | 已具备 | `GET /api/v1/assets/{id}/shots`、MCP `get_timeline` |
| 4 | 预览（缩略图 / 代理） | 已具备 | `GET /api/v1/assets/{id}/thumbnail`、`/proxy` |
| 5 | 读词级转录稿 | **本轮新增** | `GET /api/v1/assets/{id}/transcript`、MCP `get_transcript` |
| 6 | 取原始素材（不暴露真实路径） | 已具备（运营中介） | WebDAV space（admin API 交付；MCP 无此工具） |

证据说明（避免把检索信号与证据混为一谈）：检索的 per-constraint
`evidence`（confirmed/possible/contradicted/unknown）来自 `POST
/api/v1/search/shots` 的 evidence gate；MCP `search_shots` 走同一结构化端点，
每个结果都带 evidence 与得分——得分是检索信号，evidence 才是主张。MCP
`get_timeline` 枚举单个素材的全部镜头（含精确起止时间），补足"匹配切片之外的完整
时间线"。

**句级语音搜索不再依赖可选的对齐阶段**：v0.31 让 ASR 转录稿的分段时间（
`segments_json`）进入 shot 级语音通道。对齐词存在时仍以对齐词为准（最强时序，
per-asset 二选一）；没有对齐时，语音通道改用 ASR 分段时间。因此默认的
ASR-only 管线现在就能按"说过什么"精确到镜头检索，与镜头描述（语义/词法通道）
在融合层共同参与排序。退化 0-0 占位段不产生时序，依旧不可做 shot 级检索。

第 6 项是**运营中介**的：素材字节由 WebDAV space 交付，创建账号、建空间、软链
素材全部走 admin 守卫的 `/api/v1/admin/webdav/...` API，由管理员/运营者在 Hub 上
完成。当前 MCP 工具集（六个只读工具）**不含** `request_source_media`，agent 不会
经 MCP 直接请求原始素材。v0.31 的 Claude Code 插件（见下）只透传 agent token，
交付步骤由运营者完成——运营者创建 space、把 WebDAV 账号/口令交给剪辑软件。

数据与读取器此前都已存在（`transcript_words` 表、`GetAlignmentWords`、
`GetTranscript`），只是没有任何路由暴露。`internal/app` 的 `Repository` 接口本就
embed `PipelineRepository`，两个读取器都在其上，Service 无需接口改动即可调用。

## 契约变更：v0.14 → v0.15

Agent 契约版本与 skills 包同批升版，四处同步：

1. `internal/api/server.go` 的 `agentCapabilities`：`version` → `"v0.15"`，
   `allowed_actions` 增加 `read_transcript`。
2. `internal/api/server_test.go` 的契约 pin → `v0.15`。
3. `skills/timingdex/references/api-contract.md` 标题 → v0.15，增补转录稿端点说明。
4. `skills/timingdex/SKILL.md` 的 `allowed_actions` 列表增补 `read_transcript`。

`read_transcript` 归入 `allowed_actions`：与 `search_shots` 同类，都是 trusted-read
的只读能力，不触碰审批、流水线、密钥或真实路径。

### 转录稿端点

```
GET /api/v1/assets/{id}/transcript      守卫：requireTrustedRead
```

```json
{
  "asset_id": "…",
  "source": "aligned",
  "language": "zh",
  "text": "完整文本",
  "segments": [{"start_ms": 0, "end_ms": 1200, "text": "句子"}],
  "words":    [{"start_ms": 0, "end_ms": 260, "text": "词", "confidence": 0.94}]
}
```

- `source` 为 `aligned` 或 `asr`，必填。转录稿驱动的编辑器需要知道时间精度来自何处。
- `source="aligned"` 时 `words` 必须存在；`source="asr"` 时 `words` 省略，仅有
  `segments`。
- 词流**连续、跨 shot 边界**，不按 shot 切分：消费方按句子思考，强加 timingdex 的
  shot 原子性会毁掉它的编辑模型。
- **404 而非空 200**：`align` 是可选阶段（链路 `transcribe → [align] → analyze`），
  多数资产只有 ASR 无对齐；"这个资产压根没有转录稿"与"转录稿为空"是不同的事实。
  空 200 会让编辑器误以为素材是无声的。

### 回退逻辑

```
GetAlignmentWords(assetID)
  ├─ 有可用时序词（TranscriptFromAlignmentWords 非 nil）→ source="aligned"
  │         升格为规范 Transcript 填充 text/segments，words 原样带出；
  │         language 取 GetTranscript 的值，无则留空
  └─ 无词或全是退化词（EndMS <= StartMS，无可用时序）→ GetTranscript(assetID)
            ├─ 非 nil → source="asr"，words 省略
            └─ nil    → 404（APIError 信封）
```

全是退化词的 alignment run 与"无对齐"同样处理：退化词被
`TranscriptFromAlignmentWords` 丢弃后没有可用时序，回退 ASR 而非返回一个空的
"aligned"——与 pipeline 分析路径对该函数的既有约定一致。

守卫矩阵同批补上此前漏登记的
`GET /api/v1/admin/hub/worker-setup/library-roots`（admin 守卫）。

## 跨机部署（MCP 客户端证书指纹钉扎）

> **历史背景（v0.31 分支快照）：** MCP 客户端当时默认使用
> `http://127.0.0.1:8787`。当前 Hub 默认是 HTTPS；跨机和默认 TLS 部署必须使用
> `https://`，并按下文配置证书指纹。下面的行为说明以当前客户端为准。

v0.31 将 Worker 的指纹钉扎逻辑原样搬到 MCP 客户端（`cmd/timingdex-mcp/main.go`）：
`TIMINGDEX_HUB_FINGERPRINT` 设置时，用 `VerifyPeerCertificate` 校验 Hub 叶证书的
SHA-256 指纹，仅接受 64 位 hex 规范形。

- **行为约定**：`TIMINGDEX_BASE_URL` 为 `https://` 而指纹缺失时，**启动即报错退出**，
  不静默降级为不校验——静默接受任意证书正是这条边界存在的理由。`http://` 保持可用
  （本机开发）。
- **指纹获取**：`timingdex serve` 启动时打印 `Hub HTTPS fingerprint: …`，该值即
  `TIMINGDEX_HUB_FINGERPRINT`。

部署环境变量：

| 变量 | 含义 |
|---|---|
| `TIMINGDEX_BASE_URL` | Hub URL。跨机部署用 `https://<hub-host>:8787` |
| `TIMINGDEX_AGENT_TOKEN` | Hub agent token（`<dataDir>/agent-token`） |
| `TIMINGDEX_HUB_FINGERPRINT` | Hub 证书 SHA-256 指纹，`https://` 下必填 |

## MCP 工具集（六个只读工具）

`cmd/timingdex-mcp` 注册六个只读工具：`inspect_library`、`search_shots`、
`get_timeline`、`get_transcript`、`get_asset`、`get_shot`。`get_transcript`
参数 `asset_id`（来自 `search_shots` 结果），走 `GET /api/v1/assets/{id}/transcript`，
token 语义与 `search_shots` 一致（agent token / trusted read）。工具名清单由
`main_test.go` 的 `TestToolNamesRegistered` 钉死，`stdio_handshake_test.go` 断言
stdio 注册数为 6。

## Claude Code 插件

仓库根新增 marketplace 入口，插件不含编译产物——`timingdex-mcp` 需在 PATH 上：

```
.claude-plugin/marketplace.json      # marketplace 入口
plugins/claude/
  .claude-plugin/plugin.json         # 插件清单
  .mcp.json                          # stdio MCP 声明（透传三个环境变量）
  README.md                          # 安装与边界说明
```

`.mcp.json` 以 `${VAR}` 透传 `TIMINGDEX_BASE_URL`、`TIMINGDEX_AGENT_TOKEN`、
`TIMINGDEX_HUB_FINGERPRINT` 三个环境变量。

**列为 future、不进本轮**：复用 Hub `GET /api/v1/hub/worker-binaries/{platform}` 先例
由 Hub 分发 mcp 二进制。

## 消费者

- ChatCut 类 AI 剪辑前端（转录稿驱动、词级时间轴、取原始素材）
- 其他依赖本契约的 agent / MCP 客户端
- Timingdex 自有 skills 包与 MCP 工具

## 边界（本轮不做）

| 项 | 理由 |
|---|---|
| 不动 `approval_mode: human_required` | "agent 起草、人类落锤、由路由强制"是本产品明确立场；适配消费方不该顺手让掉这个卖点 |
| 不放宽 `denied_actions` | 含 `export_timeline`；"允许 agent 导出已批准计划"是可讨论的未来项 |
| 不做代理素材批量导出 | Tier 2 独立项 |
| 不做说话人归属 / 人脸聚类 | Tier 2 独立项 |
| 不改检索排序 | 会动检索 golden 基线，需独立理由 |
