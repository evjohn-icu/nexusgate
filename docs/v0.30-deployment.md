# v0.30 Deployment

## Environment Variables

Configuration precedence is: built-in defaults, sparse `$NEXUSGATE_DATA_DIR/config.json`, then environment variables. Environment values listed below are read by the Hub unless marked shell-only. Provider-specific API keys are secrets and should be supplied only through the environment or provider channels, never committed to `config.json`.

An omitted JSON field keeps its built-in default. An explicitly supplied dangerous zero or empty value is not treated as omission: for example, an enabled supervisor with `scan_interval_minutes: 0`, or an empty/unknown TLS mode, is rejected at startup.

| Variable | Default | Secret | Meaning |
| --- | --- | --- | --- |
| `NEXUSGATE_DATA_DIR` | `~/.nexusgate` | no | Hub data directory; worker tooling may override its own process directory |
| `NEXUSGATE_SOURCE_STAGING_MODE` | `none` | no | `none` or `copy` source staging mode |
| `NEXUSGATE_LISTEN_ADDRESS` | `127.0.0.1:8787` | no | Hub bind address |
| `NEXUSGATE_TLS_MODE` | `auto` | no | `auto`, `files`, or `off` |
| `NEXUSGATE_TLS_CERT_FILE` | empty | no | Certificate path for `files` mode |
| `NEXUSGATE_TLS_KEY_FILE` | empty | yes | Private-key path for `files` mode |
| `NEXUSGATE_HUB_ADMIN_TOKEN` | generated | yes | Hub administrator token |
| `NEXUSGATE_ALLOW_WORKER_PROVIDER_CREDENTIALS` | `false` | no | Permit explicitly trusted workers to receive lease-bound provider credentials |
| `NEXUSGATE_LIBRARY_SUPERVISOR` | `false` | no | Enable unattended scanning and pipeline supervision |
| `NEXUSGATE_LIBRARY_SUPERVISOR_INTERVAL_MINUTES` | `15` | no | Supervisor interval; must be positive when enabled |
| `NEXUSGATE_PIPELINE_PROVIDER_ROUTE_DEFERRAL_MINUTES` | `300` | no | Provider route cooldown |
| `NEXUSGATE_MINIMUM_FREE_SPACE_BYTES` | `0` | no | Disk preflight floor; zero disables it |
| `NEXUSGATE_TRUSTED_READ_NETWORKS` | built-in private ranges | no | Comma-separated CIDR allowlist |
| `NEXUSGATE_PROVIDER_TIMEOUT` | provider default | no | Legacy provider timeout in seconds |
| `NEXUSGATE_VOLC_ASR_URL` | built-in URL | no | Legacy Volcengine ASR endpoint |
| `NEXUSGATE_LOG_FORMAT` | `text` | no | Shell/runtime logging format: `text` or `json` |
| `NEXUSGATE_LOG_LEVEL` | `info` | no | Shell/runtime log level: `debug`, `info`, `warn`, or `error` |
| `NEXUSGATE_WORKER_CONFIG` | `~/.nexusgate/worker.json` | no | Shell-only worker config path |
| `NEXUSGATE_TLS_DIR` | `./deploy/tls` in Compose | no | Shell-only Compose mount source for TLS files |
| `NEXUSGATE_MEDIA_ROOT` | required in Compose | no | Shell-only Compose source path for read-only media |
| `NEXUSGATE_BIND` | `127.0.0.1` in Compose | no | Shell-only Compose published-address prefix |

The default Hub endpoint is HTTPS. Browser administration is intentionally limited
to a direct HTTPS connection to the Hub: the browser token establishes an in-memory
HttpOnly Session with CSRF protection, and the Hub does not trust `Forwarded` or
`X-Forwarded-*` headers. `NEXUSGATE_TLS_MODE=off` is a controlled HTTP mode for
non-browser clients, not support for an unconfigured TLS-termination proxy.

Legacy provider base URLs may also be overridden with `NEXUSGATE_<API_KEY_ENV>_BASE_URL`, for example `NEXUSGATE_STEP_API_KEY_BASE_URL`. This is a non-secret endpoint setting. `NEXUSGATE_FILTER_LOG` is test-only and is not a deployment setting.

Provider API key variables such as `STEP_API_KEY`, `DASHSCOPE_API_KEY`, `GEMINI_API_KEY`, `ARK_API_KEY`, `ARK_AGENT_PLAN_API_KEY`, and `ARK_CODING_PLAN_API_KEY` are provider variables, not `NEXUSGATE_*` settings; all are secret.

The historical `NEXUSGATE_HUB_URL` and `NEXUSGATE_WORKER_NAME` examples in older deployment guides are shell-only placeholders for enrollment commands, not variables read by NexusGate. Pass their values to `worker enroll` flags instead.

## Doctor Exit Semantics

`nexusgate doctor` exits `0` when the database is readable and its integrity check succeeds. Advisory warnings, such as missing optional media tools or unhealthy library roots, do not change that exit status. It exits non-zero when the diagnostic cannot run or the database integrity check fails. The same integrity rule applies to `nexusgate doctor --json`.
